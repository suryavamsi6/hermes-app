# Hermes · full mobile design

This is a dark-mode design prototype, combining the approved `REDESIGN.md` and `BOTS-2.5D.md` decisions with the new Attention carousel. The Appllama MCP was unavailable; the choices below apply the installed skills' encoded standards, not claimed research on live apps. The HTML is a visual and interaction study, not a native implementation or proof of device performance.

## Shared language

Canvas `#09090b`; surfaces `#151518`, controls `#222225`, separators `#303033`, primary text `#f2f2f1`, secondary `#b0b0b0`. Warm `#d97757` is the single action and active-progress accent; red is reserved for actual failure. Bot identity colors belong to the character, not the action system. Use a 4 pt grid, 16 pt gutters, 8 pt related gaps, 24 pt between groups, and at least 44 pt interactive targets. Actions are capsules, cards 16 pt, inner fields 8 pt; use native continuous corners. System typography follows a platform ramp; counts and times use tabular figures. Native implementation resolves semantic colors for both appearances, respects safe areas and Dynamic Type, and uses native navigation and symbols. **Appllama:** semantic colors, one accent, one grey family, shape lock, typography hierarchy, safe areas.

## Attention carousel and morph

**Carry forward:** replace the oversized home hero with compact, scannable content and preserve conversation access, status, search, settings and add. Keep the seeded, layered bot identities and textual state labels. **New:** Attention occupies the top of Home. Five example cards represent approval, running reply, failed step, time and weather. The center card faces forward; neighbors sit lower on a concave arc and rotate inward around Y, peeking from the edges. Each card has its associated bot's small layered face. The card's headline metric is retained in its circular node: approval count, elapsed time, failed count, clock time, or temperature. Ring arcs are visual indicators, not invented percentages: time and temperature use an open decorative arc; counts and elapsed time are not represented as completion percentages. Labels remain visible and accessible.

Dragging directly moves the arc; release projects velocity to a neighboring card and settles with a damped spring. Grab interrupts a spring. The active item remains centered, and accessible previous/next controls provide an alternative. As Home scrolls, a fixed-height clipped region translates and fades the arc into a pinned row of five rings; no header height is animated. The active ring is warm and retains the metric; other rings remain neutral, except the failed item's red failure indicator. Tapping a node selects it and returns Home to the top, re-expanding that card. A card opens its associated chat, steps or routine context in production; time and weather can open their relevant detail when available. **Appllama:** gesture spring and spatial continuity, transform/opacity only, one accent, state conveyed in words, 44 pt targets, push goes deeper.

The morph follows scroll position, not a separate continuous flourish. The prototype includes an explicit toggle so both states can be compared. Under Reduce Motion use stable poses and a short cross-fade or immediate change; selection remains possible without dragging. In native code keep gesture and scroll values on the UI thread, use a fixed clip, suspend offscreen work and measure 60 fps in a release build. Do not animate reading text for decoration. If there are no attention items, show a quiet “All caught up” state with a path to the assistants; loading retains the card footprint; unavailable weather says so rather than fabricating a reading. **Appllama:** motion purpose, frequency gate, Reduce Motion, full state cycles, performance.

## Home list

**Carry forward:** “Continue” is a compact primary conversation row, followed by “Your assistants”; identity, preview, timestamps, status, search, settings and add remain. A row is the action, with a subtle highlight on press. Keep row-shaped loading placeholders, an add-assistant empty state, and an inline retry for connection errors. **New:** the Attention area sits above this same list, and the pinned ring row leaves the list usable while scrolled. Native list navigation pushes the conversation; back returns to the same scroll position. **Motion:** ordinary platform scrolling, no row entrance stagger. **Appllama:** typography hierarchy, full state cycles, frequency gate, push goes deeper.

## Chat and 2.5D bots

**Carry forward:** unboxed assistant text aligns with steps and activity; the user message keeps its subdued bubble. Keep markdown, links, selection, streaming, long-press actions and long-message scrolling. The native header contains the bot identity and a small face. Its shallow stack has a contact shadow, darker side plane, face plane and two separate eye planes; seeded shape and colors persist at every size. Text labels accompany mood. Approval outranks live work; busy becomes thinking or working; completion briefly becomes success; failure becomes error; typing becomes listening; otherwise idle. Sleeping is only an explicit proposed state, not inferred. **New:** the running example shows the working pose in the header and the same identity on its Attention card. **Motion:** minimal mood transition in 200–280 ms; restrained nod for working, no continuous animation under Reduce Motion. Direct bot drag, where offered, separates layers and springs back without competing with scrolling. **Appllama:** hierarchy, state change with purpose, motion frequency gate, full state cycles.

## Steps pill and page

**Carry forward:** a neutral compact pill says “3 steps · In progress” or a worded failure state and has a 44 pt tap area. It pushes a dedicated ordered, divided list; standard back returns to chat. Rows show human-readable tool name, status, input preview and raw tool name; expansion reveals selectable input/output and actionable error guidance. Failure alone is red and also named in text. Remove swipe-to-open and repeated boxed step cards. **New:** the failed Attention item links to the relevant turn's steps page. **Motion:** native push/pop and quiet press feedback only. **Appllama:** push goes deeper, one accent, full state cycles, frequency gate.

## Activity line

**Carry forward:** a small warm status mark and factual line such as “Searching the web…” sit below the steps pill; announce meaningful changes politely. Use “Working…” when detail is unknown. Remove rotating phrases and perpetual opacity pulses. Completion yields to the reply without displacing text already being read. **New:** the running card exposes the same work at Home. **Motion:** progressive content reveal, no decorative movement. **Appllama:** purpose, reading content stays still, perceived performance.

## Composer

**Carry forward:** one 16 pt input surface includes quiet attach and voice controls and one warm send action when sending is possible. During a run, Stop occupies that position; if steering is supported and text exists, Add to reply can occupy it while Stop remains separately reachable. Preserve drafts, attachment, slash command, voice and edit behavior. Grow to a bounded multiline field, follow the actual keyboard and respect the bottom safe area. Disabled is neutral; failures retain the draft. **New:** the mock shows a composed message ready to send. **Motion:** native keyboard tracking and subtle press feedback, without a send pop. **Appllama:** one accent, native controls, one label per intent, frequency gate.

## Approval card

**Carry forward:** inline in the assistant turn, a 16 pt card states tool, target and consequence before the decision; expandable selectable details expose the command. “Allow once” is the only warm primary; “Deny” remains visible and neutral, with other scopes only when supported. Pending disables actions and communicates progress; failure preserves the request and offers retry; never approve automatically. **New:** the approval Attention card summarizes this same request and opens its conversation. **Motion:** no ornamental warning animation; state updates are quiet. **Appllama:** one primary action, typography hierarchy, full state cycles.

## Attention data and limits

- **Approvals:** inspect assistant turns in `chats[botId].turns` for `approval` (the existing `useApprovalBots` selector provides bot IDs). `Approval.title` and `detail` supply the request; associate the bot and turn. Tool/target should only be shown when reliably available in those fields; otherwise show the request text.
- **Running:** `BotChat.busy` and the latest streaming assistant turn identify live work; `useActivity` provides the phrase and `face-state.ts` determines mood. A turn has optional `at`, but it is a message timestamp, not a guaranteed run-start timestamp. Add a trustworthy run-start timestamp for elapsed time; until then show “Running” instead of inventing a duration.
- **Failed:** inspect assistant `steps` for `status === 'failed'`, using `tool`, `preview` and `result`, and link to that bot and turn. Failed routines are separate: `TodayCard` already loads jobs and uses `isFailing`.
- **Time and routine:** use the device's localized clock and timezone. `backend.listJobs(bot)` returns jobs with `nextRun`, `paused`, name and schedule; show the next enabled routine when its time is reliably comparable. The formatted `nextRun` string may require a raw timestamp for correct ordering. If none exists, say “No routine scheduled.” Associate the face with the next routine's bot; use the primary bot when there is none.
- **Weather:** the repository exposes a weather plugin/tool in demo metadata, not a home weather feed. A location-aware, permission-respecting forecast source with timestamp and units is required; the Bengaluru values in this mock are illustrative. Show unavailable or stale state until real data arrives, and use the chosen assistant's face.

## Shipping validation

This prototype is dark only by request. Before shipping, verify semantic light and dark colors, contrast, safe areas, large type, long content, all loading/empty/error states, keyboard, approval recovery, every navigation/back path and Reduce Motion. Record and inspect the complete native flow on a simulator and measure a release build on the slowest supported device; HTML frame rate is not native performance evidence. **Appllama:** simulator loop, accessibility and performance.
