# Implementation plan: approved mobile design

## Scope and decisions

Implement the approved `FULL-DESIGN.md`, `REDESIGN.md`, `BOTS-2.5D.md` and corresponding `mock/*.html`, with the owner's final corrections taking precedence: **no carousel navigation buttons**; touch/drag and ring-node selection only; cards move side by side along an inverted arc and never pass behind one another. The steps pill is **drag-only**, with no visible navigation buttons. Keep a screen-reader accessibility action on the pill so the same destination remains operable without a drag; it is not a visible button. Ring nodes are accessible touch targets and provide direct selection even with Reduce Motion. Red is reserved for actual failure; use warm accent for active work and neutral states elsewhere, with text labels as well as color.

Current code facts that affect sequencing:

- Home is `app/index.tsx`, a `FlatList` with a hero and `TodayCard` in its header. `useApprovalBots` returns IDs, not approval details; live chat state is in the private store in `src/app-state.tsx`.
- `src/history-turns.ts` defines `loadTurns`, but `src/app-state.tsx` currently uses `parseMessages` and its own `toTurns` in both `loadChat` and `syncChat`; it does not call `loadTurns`. `syncChat` may replace turns and their IDs, while busy chats are protected. History helpers can preserve steps; verify their matching rules before integration. History may not contain approvals or step data, so never claim completeness where the backend doesn't supply it.
- `AssistantTurn.at` is a message time, including a reused old time on retry, not a reliable run start. `applyStream` can split one run into several assistant turns. `useActivity` already derives the running phrase. `src/ui/steps-page.ts` caches a snapshot while the steps route prefers matching live steps.
- `TodayCard` queries `backend.listJobs` for failed routines. `Job.nextRun` is a formatted string (including demo values such as “Tonight”), not an orderable timestamp. Keep failed routine access during the redesign; do not infer a next job by parsing these strings.
- The only weather references are demo plugin metadata in `src/demo-backend.ts`, including a `get_weather` tool and API-key requirement. There is no home forecast feed, location, or weather cache. No fabricated weather or network call through a chat tool.
- System Reduce Motion is already observed live by `src/ui/live-surface.ts` and used by `src/ui/motion.tsx` and `src/ui/bot-face.tsx`; there is no separate app preference to invent.
- Gesture Handler appears in `package-lock.json` as a transitive/peer install, but is absent from direct dependencies and there is no `GestureHandlerRootView`. The carousel requires it as an explicit SDK-compatible dependency: install with `npx expo install react-native-gesture-handler`, update `package.json` and `package-lock.json`, and wrap the root in `app/_layout.tsx`. Existing Reanimated, Worklets and SVG are sufficient otherwise. No other new dependency is required for the core phases.

## Cross-phase release gate

Each phase is a small complete change with working UI and independently releasable behavior. Run `npm run typecheck` and the full `npm test` after every phase, plus the focused tests and device checks listed below. Add new test files to the explicit `test` script in `package.json`; follow `test/face.test.mjs` / `test/face-entry.ts`: bundle RN-free TypeScript with esbuild and test using `node --test`.

**Critical restore constraint:** `npm test` runs `pretest`, and CI and `.github/workflows/release.yml` also run restore scripts before typecheck. `scripts/restore-app-state.mjs` overwrites `src/app-state.tsx` from `scripts/app-state-b64/p1.txt` through `p6.txt`; `scripts/restore-bubble.mjs` overwrites `app/bot/bits.tsx`, `src/chat-model.ts`, `src/ui/steps-row.tsx`, and `test/sse.test.mjs` from `scripts/bubble-b64/`. For each changed restored source, update its corresponding encoded payload in the *same phase* (or deliberately replace the restore mechanism and update both CI and release in a dedicated compatible change). Verify clean checkout -> restore -> typecheck -> test leaves intended sources unchanged. Never rely on local tests that bypass this gate. Run the bridge-backed suite with `HERMES_BRIDGE_SRC` set to a real `hermes-bridge` checkout as in CI; do not change its protocol. Validate Android prebuild and release APK build in the release workflow without publishing a release or changing version/signing configuration.

- Add a narrow stable selector over the existing live store and a pure attention-item selection function with stable keys, deterministic order, counts and explicit destinations. Preserve selection by key when items change and select a sensible neighbor when one disappears.
- Record an optional trustworthy run-start timestamp once at a new local run's start, including retry, and propagate across `applyStream` split turns and reconnects without resetting it. A next routine may only appear when an actual comparable timestamp is available; otherwise show local time and a neutral routine fallback. Preserve steps across an unchanged refresh without reintroducing resolved approvals; if a turn cannot be safely matched, don't attach a failure to another reply. Test changed history, in-flight runs, unknown history steps, new-chat reset and reconnect. Failures absent from backend history must not be presented as durable across restart.
- Replace the large Home hero with compact Continue and Your assistants rows, preserving search, settings, add, menus, preview, status, unread, scroll position, loading and errors. Until the carousel lands, show compact actionable attention summaries rather than inert UI. Card destinations: approval/running -> bot chat; failed -> call `setStepsPage` with the actual steps, then push `/steps/[botId]/[turnId]`; time has no invented destination. Handle vanished turns gracefully.
- **Verify:** pure selection tests for empty/loading, multiple bots, precedence, stale approvals, split runs, missing timestamps, failures and stable ordering; existing history/bridge tests plus refresh/retry tests. Device-check live approval resolution, running elapsed, failed-step route, empty and disconnected Home.

## Phase 4 — Attention carousel

**Paths:** add `src/ui/attention-carousel.tsx`, `src/ui/attention-geometry.ts`, `test/attention-geometry-entry.ts`, `test/attention-geometry.test.mjs`; change `app/index.tsx`, `app/_layout.tsx`, `package.json`, `package-lock.json`.

- Install and explicitly configure Gesture Handler as described above. Add `AttentionCarousel` to the Home header, backed by Phase 3 items and real bot identities. Show appropriate loading and empty states; support variable item count, narrow screens, long labels and large type. There are no previous/next controls or hidden navigation buttons: direct horizontal pan, flick and touchable labeled ring nodes are the selection paths. The selected actionable card opens its real context; time is informational unless a real destination exists. Ring nodes remain available when expanded and when reduced motion is on, with 44-point targets and accessibility labels/selected state.
- Geometry is a pure worklet-compatible function of fractional index and measured viewport/card width. Center card is highest, neighbors progressively lower on an inverted concave arc and tilt inward. Use ordered horizontal positions with a minimum separation greater than projected card widths plus a gap at **every fractional position**, including during drag and settle; clip at viewport edges rather than using depth, z-index swapping, overlapping or cards passing behind each other. Test projected bounds across widths, fractional indices and rotation; reduce rotation or card width if required to maintain this invariant. A fixed-height clip avoids layout animation.
- Gesture Handler pan activates only after horizontal intent, yields vertical motion to the list, captures an in-flight shared value, projects release velocity to a clamped index and uses a velocity-preserving Reanimated spring; interruption works on a new grab. All per-frame work stays on UI-thread worklets and animates transform/opacity only; update React selection only at settle, with a single synchronized route/node action. No timers or React state per frame. With Reduce Motion, retain touch selection and use immediate stable poses or a short cross-fade, without spatial spring travel.
- **Verify:** geometry node tests include both endpoints, intermediate positions, monotonic order/non-overlap, variable widths/counts, bounds, velocity projection and empty/single item; selection changes under item removal. On iOS and Android test touch-only navigation, interrupted flick, vertical scroll, rotation, accessibility, Reduce Motion and actionable routes.

## Risks and acceptance by phase

- **FlatList and pinned row:** recycled cells, sticky geometry, overlay hit testing and accessibility duplication can hide content or interfere with scrolling. Reserve fixed space, expose only the active representation, and test scroll/back/resize with a long list.
- **Android graphics:** perspective and rotation can cause clipping, overdraw or low frame rate; profile release builds and reduce complexity, never trade away non-overlap or truthful labels.
- **Steps pill:** the current implementation supports tap and right swipe; the requested drag-only behavior removes tap and the visible chevron. Gesture conflicts and discoverability are real risks: retain a clear drag affordance, 44-point target, and screen-reader action; verify all navigation paths.
- **State and backend:** asynchronous history sync may replace turns, `at` is not run start, and remote history may omit steps. Do not lose a live run, resurrect approval, invent elapsed time or assert durable failure beyond available data. Weather and routine scheduling need trustworthy sources.
- **CI and release:** restore scripts overwrite edited code; update the exact encoded payloads alongside source changes and verify both clean CI and release sequences, including real `hermes-bridge` tests and Android prebuild/release compilation.

Final phase acceptance checklist:

1. **Chat/steps:** unboxed reply and redesigned activity, approval and composer preserve existing chat functions; drag-only pill and accessible action open a live ordered steps page; tests and restore gate pass.
2. **Bot identity:** all existing identities render layered 2.5D at every size; mood priority and motion/Reduce Motion policies pass tests and device inspection.
3. **Data/Home:** truthful approval, running, failed and device time summaries link correctly; elapsed is based on a known start; compact Home preserves existing destinations and sync behavior; pure and bridge tests pass.
4. **Carousel:** touch drag/flick and ring-node selection work without navigation buttons; cards remain side by side throughout the inverted arc; geometry tests and device gesture checks pass.
5. **Morph:** scroll produces a stable pinned ring row, ring selection re-expands the right card, FlatList interaction and accessibility work, and release-device motion/performance validation passes.
6. **Weather later:** only real, permission-respecting, fresh data is displayed, with explicit unavailable/stale states and passing source-specific tests; core phases ship without it.
